# GitHub Sentiment Monitor

Учебное Python-приложение для потокового анализа Issues и комментариев публичных репозиториев GitHub. Приложение периодически получает обновления через GitHub REST API, определяет тональность сообщений, отслеживает всплески негативной активности и группирует похожие обращения.

## Возможности

- периодический опрос GitHub REST API;
- загрузка Issues и комментариев с исключением Pull Requests;
- инкрементальная синхронизация и защита от повторной загрузки;
- локальное хранение сообщений в SQLite;
- классификация на положительные, отрицательные и нейтральные сообщения с помощью Hugging Face Transformers;
- автоматический выбор устройства для классификации: NVIDIA GPU через CUDA при доступности, иначе CPU;
- анализ активности и тональности во времени;
- выявление всплесков негатива на 15-минутных интервалах;
- группировка похожих сообщений с помощью TF-IDF и KMeans;
- фильтрация, таблица сообщений и экспорт CSV;
- демонстрационный набор данных для проверки интерфейса без обращения к GitHub и загрузки модели.

## Быстрый запуск в Windows

**Требования:** Python 3.10–3.12 (рекомендуется Python 3.11) и подключение к интернету. Для первой установки желательно иметь не менее 8 ГБ оперативной памяти и свободное место для PyTorch и модели Hugging Face.

1. Установите Python 3.11 с сайта [python.org](https://www.python.org/downloads/). При установке включите добавление Python в PATH.
2. Скачайте репозиторий через кнопку **Code → Download ZIP** и распакуйте архив либо клонируйте его командой:

   ```powershell
   git clone https://github.com/USERNAME/github-sentiment-monitor.git
   cd github-sentiment-monitor
   ```

3. Запустите файл `run_windows.bat`. Он создаст виртуальное окружение `.venv`, установит зависимости и запустит Streamlit.
4. Откройте адрес, который появится в консоли (обычно http://localhost:8501).

При первом запуске классификатор загружает модель с Hugging Face. Это может занять некоторое время и потребовать дополнительного дискового пространства. Последующие запуски используют локальный кэш модели.

### Использование GPU или CPU

Устройство выбирается автоматически при запуске приложения:

- если PyTorch обнаруживает доступную CUDA-совместимую видеокарту NVIDIA, модель тональности запускается на GPU;
- если CUDA недоступна, модель запускается на CPU. Отдельно переключать режим в интерфейсе не нужно;
- выбранное устройство отображается в боковой панели приложения.

GPU ускоряет именно инференс модели тональности. Получение данных из GitHub, SQLite, обработка таблиц Pandas, TF-IDF/KMeans и анализ временных интервалов продолжают выполняться на CPU.

На Windows наличие видеокарты NVIDIA само по себе не гарантирует использование GPU: необходима сборка PyTorch с поддержкой CUDA и совместимый драйвер NVIDIA. Чтобы установить подходящую сборку, откройте [официальный селектор установки PyTorch](https://pytorch.org/get-started/locally/), выберите Windows, Pip, Python и совместимую версию CUDA, затем выполните предложенную команду установки внутри виртуального окружения проекта. После установки проверьте доступность CUDA:

```powershell
.venv\Scripts\python.exe -c "import torch; print('CUDA доступна:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'Будет использоваться CPU')"
```

Если команда выводит `CUDA доступна: False`, приложение продолжит работать на CPU. Для диагностики проверьте драйвер NVIDIA и установленную сборку PyTorch.

### Ручная установка в Windows

Откройте PowerShell в каталоге проекта и выполните:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell запрещает активацию виртуального окружения, можно не активировать его и запускать команды через `.venv\Scripts\python.exe`.

## Настройка репозиториев GitHub

В боковой панели приложения перечислите публичные репозитории в формате `owner/repository`. Допускается ввод через запятую или с новой строки:

```text
pallets/flask,streamlit/streamlit,psf/requests
```

GitHub Token необязателен для публичных репозиториев, но повышает лимит REST API. Токен можно ввести непосредственно в интерфейсе приложения. Не публикуйте токен в коде, ноутбуке или открытом репозитории.

При необходимости можно скопировать `.env.example` в `.env` и задать параметры по умолчанию. Файл `.env` исключён из Git через `.gitignore`:

```dotenv
GITHUB_TOKEN=
GITHUB_REPOSITORIES=pallets/flask,streamlit/streamlit
SENTIMENT_MODEL=cardiffnlp/twitter-xlm-roberta-base-sentiment
DATABASE_PATH=data/messages.db
```

## Google Colab

Для запуска в Google Colab откройте `Google_Colab_Launch.ipynb` и последовательно выполните ячейки. Ноутбук предложит загрузить ZIP-архив проекта, установит зависимости, проверит доступность GPU и запустит Streamlit через встроенный прокси Google Colab. LocalTunnel не используется.

Чтобы использовать GPU в Colab, до запуска ячеек выберите `Среда выполнения → Сменить среду выполнения → T4 GPU` (вариант ускорителя зависит от доступности и тарифа). После установки зависимостей ноутбук покажет, обнаружен ли GPU. Если GPU не выдан или PyTorch не видит CUDA, приложение автоматически использует CPU.

## Как устроена обработка

1. Приложение периодически получает через GitHub REST API Issues, обновлённые после сохранённого курсора.
2. Pull Requests отбрасываются.
3. Для изменившихся Issues загружаются комментарии.
4. Записи сохраняются в SQLite по уникальным идентификаторам GitHub, повторная загрузка не создаёт дубликаты.
5. Новые или изменённые сообщения передаются модели тональности. PyTorch автоматически выбирает CUDA GPU, если он доступен, иначе используется CPU.
6. Аналитический модуль строит временные ряды, определяет всплески негативной активности и группирует похожие сообщения.

Это учебная реализация near-real-time polling, а не распределённая событийная система на базе Kafka или Flink. Для получения обновлений вкладка приложения должна оставаться открытой.

## Методика обнаружения всплесков негатива

Сообщения агрегируются по 15-минутным интервалам. Сигнал фиксируется, если одновременно выполнены условия:

- не менее трёх отрицательных сообщений в интервале;
- доля отрицательных сообщений не менее 60%;
- число отрицательных сообщений превышает исторический порог: среднее плюс 2,5 стандартного отклонения по предыдущим интервалам.

Это эвристический критерий. В исследовательской работе рекомендуется проверить его на вручную размеченной выборке и сравнить с альтернативными порогами.

## Ограничения

- GitHub REST API предоставляет периодические обновления, а не непрерывный поток событий.
- Скорость получения данных ограничена лимитами GitHub API.
- Модель Cardiff NLP обучалась на мультиязычных сообщениях из Twitter, а не на технических Issues GitHub. Сарказм, логи и короткие сообщения могут классифицироваться неверно.
- Русский язык не входит в перечень языков fine-tuning, указанных в карточке используемой модели.
- TF-IDF + KMeans — базовый способ группировки; кластеры не обязательно соответствуют отдельным программным дефектам.
- SQLite рассчитана на локальный запуск одного экземпляра приложения. Для совместного многопользовательского развёртывания потребуется серверная база данных и отдельная инфраструктура.
